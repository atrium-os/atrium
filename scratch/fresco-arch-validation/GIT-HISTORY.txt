70e02dc 2026-05-04 step 9: texture op (vkImage + sampler + per-slot descriptor sets)

Bundle gains a second op (id 0x1001 = atrium-core.texture):
op_texture.comp identity-writes per-instance models, pipe_texture.{vert,frag}
sample a sampler2D at corner UVs.

OpKind enum (Rect | Texture) selects descriptor-set shapes at AOT
compile time. Texture's render set adds binding 2 = combined_image_sampler.
A linear/clamp sampler shared across slots, and a per-slot descriptor

replacement) avoid mid-frame descriptor writes against in-use sets.

OpFrameResources gained kind + parametric node/instance sizes (rect: 32B
each, texture: 16B each). Render-pool sizing differs: Rect allocates
one set; Texture pre-sizes for SLOT_CAP=64 concurrent slots.

Renderer::render() restructured: per-op DrawPlan structs are built in a
pre-record phase (resolving handles, writing scene buffers, ensuring
per-slot descriptors), then the recording loop walks plans without
fighting borrow-checker over self.{op_pipelines,op_frames,resources}.
Each plan gets compute (counter zero + dispatch + barrier) outside the

f935445 2026-05-04 step 7: rect compute kernel dispatch + atomic-counter readback

Per-op GPU buffers (scene host-visible, instance device-local, counter
host-visible) live in OpFrameResources, allocated at load_bundle from
manifest.gpu_resources.max_instances. Persistently-mapped scene buffer

7660ae0 2026-05-04 step 5a: atrium-rpc-display payload schemas

The display dictionary at CLASS_DISPLAY=1 (per atrium-rpc-display
already declared in step 1) gets concrete payload structs and
encoding helpers. No transport yet — that's step 5b. This commit
just locks the wire shapes the test client (step 10) and the
server dispatcher (step 5b) will exchange.

Encoding: postcard, per atrium-rpc.md §10's "postcard for
Rust↔Rust, hand-rolled binary for performance-critical opcodes."
For the POC every payload is Rust↔Rust and none is hot enough to
justify hand-rolled binary; postcard is the right default. Can
swap individual ops to fixed-binary later without touching the
envelope or other ops.

== Public surface ==

  encode<T: Serialize>(&T)         → Vec<u8>
  decode<T: Deserialize>(&[u8])    → T

  control::OP_*                     u16 envelope opcodes
  scene_ops::ATRIUM_CORE_*          u32 scene op-IDs (registry §3.4)

== Control payloads ==

  SlotSetPayload          { slot_id: u32, hash: [u8;32] }   33 B
  SlotClearPayload        { slot_id: u32 }                   1 B
  SceneFrameBeginPayload  {}                                 0 B
  SceneFrameEndPayload    {}                                 0 B
  SceneNodeSetPayload     { node_id, op_id, params: Vec<u8> }
  SceneNodeClearPayload   { node_id }
  WindowCreatePayload     { width, height, title }
  WindowPresentPayload    { window_id }

The Vec<u8> in SceneNodeSetPayload is the load-bearing design
choice: outer envelope schema stays stable as the per-op
vocabulary grows. New ops drop in without touching the
SCENE_NODE_SET payload schema. Inner params are decoded
op-specifically by the host shim after dispatch on op_id.

== Scene op param schemas ==

  RectParams      { x,y,w,h, r,g,b,a: f32 }
  TextureParams   { x,y,w,h: f32, slot_id: u32 }

Both are postcard-encoded on the wire. RectParams' field order
matches bundles/atrium-core/compute/op_rectangle.comp's GPU
SceneNode (vec2 pos + vec2 size + vec4 color), so step 7's
host→GPU rewrite is a straight memcpy after postcard decode.

Wire shape vs GPU layout are deliberately decoupled: postcard on
the wire (evolvable, varint-compact); fixed-binary in the GPU
buffer (cache-friendly, GPU-readable). The host shim translates
between them on each SCENE_NODE_SET.

TextureParams ships its schema in step 5a so the test client can
emit Scene B without further protocol changes; the actual op
implementation lands in step 9.

Homebrew's /opt/homebrew/lib isn't on macOS's default dylib search
path under SIP. Without help, ash::Entry::load() does
dlopen("libvulkan.dylib") which fails. Three workaround options:
DYLD_FALLBACK_LIBRARY_PATH (env-fragile), explicit Entry::load_from
(hardcodes a path), or rpath at link time.

Going with rpath: target.aarch64-apple-darwin rustflags add
"-Wl,-rpath,/opt/homebrew/lib" + "-Wl,-rpath,@executable_path".
Verified via otool -l: LC_RPATH entries embedded. dlopen
resolves libvulkan.1.dylib via the rpath chain.

(Intel macOS: /usr/local/lib is on the default fallback path, so
no rpath needed there. Linux/FreeBSD: ld.so finds libvulkan via
ld.so.cache or LD_LIBRARY_PATH.)
