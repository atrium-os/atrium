# Bench v7 + compile time, R9700 under Ubuntu (2026-11-16)

Box: R9700 (GFX1201), Xeon E-2288G, Ubuntu kernel 7.0.0-38, Mesa
(RADV/ACO) 26.0.8-1ubuntu0.3. GPU idle before each run (runtime-suspended
under BACO, no other clients).

| File | What |
|---|---|
| `bench_v7.out` | bench v7 exactly as staged on 2026-11-04 (script sha256 47642f50…, generated at atrium 5c022033). The staged copy was gone from the box (Ubuntu reinstalled since); the same file was taken from the owner's Mac. |
| `bench_v7_main.out` | the same 16 benches regenerated by `bench-script` at main 9ab59de4 (the four desktop op_* SPIR-V files taken from the v7 script, since their slang sources have not changed since 5c022033 and slangc is not installed), with the compile section: RADV `vkCreateComputePipelines` x10 with `RADV_DEBUG=nocache MESA_SHADER_CACHE_DISABLE=1`, ours `compile-time` x10 (built on the box at 9ab59de4), same CPU. |
| `bench_main_fresco_only.out` | first run at 9ab59de4 before the desktop SPIR-V was found: fresco cases only, on a GPU that had not yet seen a fault this boot. |
| `compile_v7.out`, `compile-section.sh` | the compile section over v7's own SPIR-V (older raster.comp), same tools. |
| `dmesg-amdgpu.txt` | amdgpu kernel messages over the session. |

`compile-time` at 9ab59de4 = the d43749fe tool with fac48fd5 and 3a70d158;
`bench-script` output at 3a70d158 and 9ab59de4 is byte-identical.

## Faults

- v7 (5c022033 compiler): raster @96 faulted (TCP, VA 0x210024000) and
  timed out; raster @64 hit the 2 s ring timeout on its repeats. 130 fault
  lines, 37 ring timeouts of comp_1.1.0 / comp_1.0.1, each followed by
  "reset succeeded".
- main 9ab59de4: no fault in the fresco-only run. In the full run,
  glyph_run @16 VGPRs wrote past the end of its instances buffer (TCP
  faults at 0x22120b000-0x221210000, the instances buffer ends at 0x22120aea0) on
  some repeats: 50 fault lines, 14 ring timeouts, all reset. Spilled raster
  ran to completion with wrong pixels; nothing in dmesg.
- GPU left idle (runtime-suspended) after the runs.

Why the spilled benches go wrong is not investigated: the compiler's spill
code, or the bench's scratch ring (`bench_ring`) at these sizes. The
oracle's `spill_*` jobs (16 VGPRs, small inputs) matched in v19.
