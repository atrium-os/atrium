# Hospes H1: loader and runtime (2026-11-11)

Step H1 of `docs/spec/hospes.md` §15: `hospes-elf` and `hospes-rt` parse, map, relocate,
set up TLS and threads, and allocate. Loader fixtures pass on FreeBSD amd64 and arm64, and
the isolation probe passes in capability mode.

## 1. What was built

| Piece | Where | What it does |
|---|---|---|
| `hospes-elf` | `hospes/hospes-elf` | Safe (`forbid(unsafe_code)`), `no_std` ELF64 parser (§5.1). It returns segments, TLS, RELRO, dynamic tags, symbols with versions (`DT_VERNEED`/`DT_VERDEF`/`DT_VERSYM`), RELA relocations mapped to a per-machine `RelocKind`, and `DT_RELR` expanded. It refuses `PT_INTERP`, text relocations, `DT_REL`, W+X segments, executable stacks, overlapping or misaligned `PT_LOAD`s and unknown relocation types. Hard limits: 64 phdrs, 200k symbols, 2M relocations, 4 GiB span. |
| `hospes-rt::sys` | `hospes/hospes-rt/src/sys` | Raw system calls, with no libc. FreeBSD is the product (carry-flag errors, `thr_new`, `_umtx_op`, `sysarch`, `cap_enter`). Linux is a development backend (`clone` trampoline, `futex`, `arch_prctl`) for native and qemu-user testing. Both run on x86_64 and aarch64. |
| `hospes-rt::start` | `start.rs` | Our own `_start`. FreeBSD passes the argc pointer in the first register; Linux puts it at `sp`. The FreeBSD ABI note brands the static binary. |
| `hospes-rt::heap` | `heap.rs` | The allocator (§4). There are 20 size classes in 64 KiB-aligned chunks, and large blocks get their own mappings. A header per chunk lets `free(p)` work without a size, as the malloc family (H2) needs. A process-wide mapping limit is enforced (`set_limit`). The same heap is the Rust `#[global_allocator]`. |
| `hospes-rt::tls` | `tls.rs` | The glibc-shaped TCB (§5.3). On x86_64 it is variant II: `tcbhead_t` with the self pointer, `dtv`, a random canary at `%fs:0x28` (low byte zeroed, as glibc does) and a pointer guard at `0x30`; our state is at `tp+0x100`. On aarch64 it is variant I: `{dtv, private}` at `tp`, with our state below `tp`. It provides `__tls_get_addr` and a static TLSDESC resolver that preserves every register. |
| `hospes-rt::thread` | `thread.rs` | Threads with a guard-paged stack and a fresh TCB plus TLS copy each. Join uses the kernel's exit notification: `thr_exit(&state)` on FreeBSD, `CLONE_CHILD_CLEARTID` on Linux. |
| `hospes-rt::load` | `load.rs` | Reserve the span (64 KiB-aligned), map each `PT_LOAD` with its own permissions, zero the bss, register the TLS template and give the main thread its TCB. Then apply relocations in this order: RELR, then RELA, then `IRELATIVE` and ifunc-valued symbols last (their resolvers may use the GOT and the canary). Finally make `PT_GNU_RELRO` read-only. Lookup checks the library's own exports first, then the host's table, with exact version matching. Weak undefined symbols are left as 0. Unknown strong imports refuse the load, and the error lists their names. A relocation into a non-writable segment also refuses the load. aarch64 ifunc resolvers get `(hwcap \| _IFUNC_ARG_HWCAP, &__ifunc_arg_t)`. Init runs `DT_INIT` then `DT_INIT_ARRAY` with `(argc, argv, envp)`; fini runs in reverse. |
| Fixtures | `hospes/fixtures` | Nine `-nostdlib` C shared objects per machine, built with clang + lld and committed. `scripts/hospes-build.sh fixtures` rebuilds them. |
| Runner | `hospes/hospes-fixture-runner` | A static `no_std` binary. It opens the fixture, calls `cap_enter`, checks that path lookups now fail, loads the fixture against a small host table and runs it. |
| Fuzz target | `hospes/fuzz` (`cargo fuzz run elf`) | Feeds hostile ELF to `hospes-elf` and asserts that the result is self-consistent. |

There are no new external crates. Everything above is our own code, under `core` and `alloc`.

The isolation probe is library code making raw FreeBSD system calls after `cap_enter`:
`open`, `openat(AT_FDCWD)` of `/etc/passwd` and `/dev/mem`, `chdir`, `mkdir`, `unlink`,
`kill(1)`, `ptrace(PT_ATTACH)`, `execve`, and `connect`/`bind` to 127.0.0.1. Each one must
return `ECAPMODE`, and each one did.

**Real libraries, load only.** The runner's `load-only` mode maps and relocates a library
with unknown imports bound to an abort stub. It runs none of the library's code. Results:

| Widevine CDM x64 | 80.0 MiB | 4,518 | 184 | 175 | Linux, FreeBSD amd64 (capability mode) |

The handful of imports already bound are the ones the fixture table happens to share, such
as `memcpy`, `memset`, `__tls_get_addr` and `__stack_chk_fail`. The rest are the H2 shim's
job; H0 §3 already lists them. Neither library is committed, and neither is ever modified.

**Fuzzing.** `cargo fuzz run elf`, seeded with the 18 fixtures, ran 13.7 million inputs in
5 minutes (ASAN, x86_64 Linux) with no crash. The unit tests also include byte-level
truncation at every length and 20,000 seeded mutations.

## 3. Decisions taken inside the spec's room

- **Fixtures are `-nostdlib`, not glibc-built (§11.1 said glibc).** The loader is tested on
  its own, against a host table, before the shim exists. That lets every step pass or fail
  for exactly one reason. glibc-built fixtures arrive with the shim in H2, together with
  the C++ exception fixture, which needs the unwinder.
- **Linux development backend.** It is not in the spec's production design, and it never
  enters capability mode. It exists so the loader runs natively and under `qemu-aarch64`
  in seconds, without a VM. Production builds target FreeBSD only.
- **One module of static TLS.** As §5.3 planned: Hospes hosts one library per process.
  `__tls_get_addr` and TLSDESC resolve inside that module, and a TLS import from outside it
  refuses the load.
- **`IRELATIVE` last.** glibc runs ifunc resolvers in relocation order. We run them after
  every other relocation, and after the main thread has its TCB, because resolvers in
  real libraries read the GOT and the canary.
- **No `panic = "abort"` in the workspace profile.** The repo's `.cargo/config.toml` builds
  `std` with build-std, which conflicts with test harnesses under abort. The build script
  passes `panic=abort` and `-Z build-std=core,alloc` for the static runtime binaries only.

## 4. Not done in H1, and where it goes

- The §11.2 ABI layout check (it checks the shim's `glibc-abi` structs, which do not exist yet), the glibc shim, eh_frame registration and unwinding, `dl_iterate_phdr` and `/proc/self/maps`
  consistency: H2 (§5.4, §6).
- The heap's optional guard pages (§4 says "on in tests"). The heap is single-lock, with no
  per-thread caches. That is enough for H1. Revisit it with the H2 decode benchmark.
- The event loop and the channels: H2/H3.
- `madvise` probing behaviour (§6.3) belongs to the shim.
- The probe covers native FreeBSD system calls only. A Linux-ABI raw syscall from the CDM
  traps once K1 exists, and K1 adds probe cases for it.
