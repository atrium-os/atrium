# Hospes K1: trapping the foreign library's own system calls (2026-11-12)

Step K1 of `docs/spec/hospes.md` §15: the kernel hook (§13 R1) and the shim's handler for the
raw Linux system calls Widevine makes from its own code. H0 found them
(`docs/reviews/2026-11-11-hospes-h0.md`): `openat` ×14 (`/proc/self/maps` ×9,
`/proc/net/unix` ×5), `read` ×44, `close` ×14 and `rt_sigaction` ×4 (queries of `SIGILL`,
`SIGTRAP`, `SIGABRT` and `SIGSYS`). Without K1 these reach FreeBSD's table with Linux numbers.

Done-when, and where it stands:

- **"The H0 CDM run's raw syscalls all handled under Hospes":** met for that call set,
  through a test library rather than the real CDM. `trap.so` makes exactly H0's raw calls
  (the same paths, counts and signal queries) from its own text. On FreeBSD arm64 and amd64,
  in capability mode, every one is trapped and answered by the shim, and none reaches the
  kernel's table. The real CDM cannot run under Hospes until H4 extends the shim to its
  imports, so its own run is H4's first check.
- **"Isolation probe still green":** yes, on both VMs, together with every H1 fixture and
  H3's Clear Key transcript, which now runs with the trap on.

Commits: fork `atrium-os/freebsd-src` branch `atrium-os`, `c12a0dadc` (the hook) and
`501a0bb0a` (field moved after amd64's KBI-asserted ones); Atrium: this commit (module,

## 1. How it works

```
library text:  syscall / svc #0  (Linux number in rax / x8)
      │
syscallenter():  p_systrap == NULL ? ──yes──► normal FreeBSD call (one predicted branch)
      │ no
systrap_hook(td)   [hospes_trap.ko]
      │  pc-1 in a registered range?  ──no──► normal call (our own code)
      │ yes
trapsignal(SIGSYS, SYS_TRAPPED, si_addr = pc, si_syscall = Linux nr); EJUSTRETURN
      │
Hospes SIGSYS handler [hospes-rt trap.rs]: Linux nr + 6 args from the ucontext
      │
hospes-glibc syscall.rs: openat/read/close → vfs.rs; rt_sigaction → real dispositions
      │
result (or -errno) written to rax / x0; sigreturn resumes after the instruction
```

### 1.1 The kernel's part (fork, C, about 30 lines)

| Piece | Where | What |
|---|---|---|
| `p_systrap` | `sys/sys/proc.h`, `kern_fork.c` | Pointer to the process's range table. It is the last field of `struct proc`, so amd64's KBI offset asserts still hold, and fork clears it, so a child never inherits ranges. |
| `systrap_hook` | `sys/sys/systrap.h`, `kern_syscalls.c` | One function pointer, set by the module. `SYS_TRAPPED` (si_code 1). |
| The branch | `subr_syscall.c`, top of `syscallenter()` | Runs before the arguments are fetched (the call may be another ABI's). If the process has ranges, the kernel asks the hook. When the hook traps the call, it returns `EJUSTRETURN`, so the call runs nothing and every register is left as it was. If the process has ranges but no hook is loaded, the call **fails closed** with `ENOSYS`. |

There is no policy in the kernel. A process without ranges pays one load and one predicted
branch per system call.

### 1.2 The module, `hospes_trap.ko` (`hospes/kmod/hospes_trap`)

- **C glue (`hospes_trap.c`):**
  - The hook, which raises `SIGSYS` with `trapsignal`. That makes it synchronous, like a
    fault: if the signal is blocked or ignored, the process is killed rather than the call
    falling through.
  - The registration system call.
  - Freeing the table at `exec` and `exit`.
  - The unload rule: unloading is refused (`EBUSY`) while any process has a table.
- **Rust (`hospes_trap.rs`):** the table and every check on it. It is append-only and holds
  at most 16 ranges. Each range must lie inside user space and must not wrap. After `LOCK`
  nothing more can be added. The count is published with release order, so the system call
  path reads the table without a lock. It is `no_std`, `deny(unsafe_code)` apart from the
  `no_mangle` exports, and does not allocate, lock or panic on any input. It has 3 unit tests.
  This follows the D2 kernel decision (Rust by default).
- **Build:** `scripts/hospes-kmod.sh` runs `buildkernel -DKERNFAST` with `LOCAL_MODULES` and
  checks that both halves' symbols are present in the `.ko`.

**A difference from the spec:** registration is a system call the module adds
(`SYSCALL_MODULE`), not a `procctl`. A `procctl` command would have put the policy into
`kern_procctl.c`, inside the kernel. Hospes finds the call's number with
`modfind("sys/hospes_trap")` and `modstat`. Neither is allowed in capability mode, so the host
does this before `cap_enter`. The call itself is allowed in capability mode, and it only acts
on the calling process.

| Operation | Effect |
|---|---|
| `hospes_trap(1, start, len)` | add a range (`EPERM` once locked, `ENOSPC` past 16, `EINVAL` if outside user space) |
| `hospes_trap(2, 0, 0)` | lock: no more ranges |
| `hospes_trap(3, 0, 0)` | count |

### 1.3 Hospes's part

- **`hospes-rt` `trap.rs`:**
  - Installs the `SIGSYS` handler.
  - Reads the Linux call from the saved registers: on amd64 `rdi rsi rdx r10 r8 r9` with the
    number in `rax`; on arm64 `x0`–`x5` with the number in `x8`.
  - Checks the call came from a registered range (anything else ends the process), calls the
    shim, and writes the result where Linux would.
  - The loader's new `Options::trap` registers the library's executable segments and locks the
    table after mapping and before relocation, because relocation runs IRELATIVE resolvers,
    which are library code.
  - **Linux development backend:** uses Linux's own syscall user dispatch, which is the same
    mechanism. The allowed range is the host's own text, and the setting is renewed on each
    thread. The same emulation therefore runs natively on Linux x86_64. qemu-user has no
    syscall user dispatch, so there the loader warns and the fixture reports SKIP.
- **`hospes-glibc` `syscall.rs`:** `openat`, `read` and `close` go to the virtual filesystem.
  Raw calls only ever see virtual descriptors (900+); any other descriptor gets `EBADF`, and
  any other path `ENOENT`. Relative paths get `ENOENT`.
- **`rt_sigaction`:**
  - Queries are answered truthfully, from the host's real dispositions, with Linux signal
    numbers, flags and masks converted. `SIGSYS` shows our handler, as a seccomp sandbox's
    does on Linux.
  - Setting a handler is refused with `EPERM` and logged, so the library cannot replace the
    trap's handler.
- **Any other call:** `ENOSYS`, logged once per number.
- **`vfs.rs`:**
  - `/proc/self/maps` (and `/proc/<own pid>/maps`) is generated from the loader's view: the
    library's segments in Linux's format, with RELRO shown read-only, reported as
    `/opt/hospes/lib/<soname>`.
  - `/proc/net/unix` is the header line only.
  - `/dev/urandom` is served from `getrandom`.
  - The rest of the §7 table comes with H4, when the shim's `open64` will use the same table.
- **`hospes-cdm`:** looks up the trap before `cap_enter` and loads the CDM with `trap: true`.
  On FreeBSD a missing module is fatal, and the supervisor sees `Fail`.

The module got system call number 210 from `SYSCALL_MODULE` on both machines.

Two things the VM runs caught, both fixed before these results:

- **amd64's `syscall` entry does not keep `r10`.** FreeBSD's ABI lets a system call clobber
  `r8`–`r11`, so its fast entry stores `r10` (the fourth argument) in the frame's `rcx` slot
  and saves neither `r10` nor `r11`. Linux keeps every register except `rax`, `rcx` and
  `r11`, and compiled code relies on that. The handler now reads the fourth argument from
  `mc_rcx` and, on return, restores `r10` and sets `rcx` and `r11` to what Linux would
  (the return address and `rflags`). `trap.so` now checks that the argument registers come
  back unchanged, on both machines and in the raw Linux run. The first amd64 run failed on
  `rt_sigaction`, which is the call that reads the fourth argument. arm64 saves every
  register and was correct from the start.
- **amd64 asserts `struct proc`'s layout** (`p_comm`, `p_emuldata`) for its KBI.
  `p_systrap` therefore went to the end of the struct and fork clears it, as above. The
  amd64 kernel and its modules have to be built with LLVM 19, because clang 18's
  `xdr.ko`/`zfs.ko` do not load and the guest then panics at mountroot (RUNBOOK §13.2).

## 3. Open points

- **The real CDM's run is H4's first check.** It must show the same 14/44/14/4 raw calls,
  all trapped. Its reads of `/proc/self/maps` are also where R2 (anti-tamper) would show up:
  our maps lists the library's own mappings only, with no host, stack or heap lines. If
  Widevine wants more, we add lines from our real mapping table; we never patch the library.
- **ktrace/ptrace detail:** for a trapped call, the kernel's syscall-exit records show the
  previous call's number, because the kernel never fetched this one's. The SIGSYS itself is
  visible to ktrace as usual.
- **Codec host:** `hospes-codec` keeps `trap: false`. OpenH264 makes no raw calls (H0), and
  turning the trap on there would make the module a requirement for H.264 playback.
  Revisit in H5.
- **Upstreaming:** the core hook is upstream-shaped (FreeBSD's syscall user dispatch). An
  upstream version would want the range table in the kernel rather than a module, and a
  `procctl`. That is a separate proposal, for Shankar to decide on, like sysfil's.
- **The amd64 VM** boots the fork kernel only through `nextboot`. That is one-shot, so
  rerun `hospes-k1-vm.sh kernel` after a VM restart.
